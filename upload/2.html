The Baseline

Did you know about React?

React is a UI library — not a full framework. It's powerful, but intentionally minimal.

React A library for the View layer

Component-Based

Build UIs from small, reusable, declarative pieces.

No Built-in Routing

You pick and install your own router — React Router, TanStack, and friends.

SEO Challenges

Client-side rendering makes search indexing harder.

External Tools Required

Routing and data fetching must be wired up by you.

The Key Insight

Library vs. Framework

“With a library, you're the architect. With a framework, the structure is already designed — you fill in the details.”

The Foundation

Provides a predefined structure for your application.

Built-in Tools

Routing and bundling are included, out of the box.

Inversion of Control

The framework calls your code — not the other way around.

Next.js adds conventions on top of React — so your team spends less time on setup and more time on shipping.

Rendering — 01

How React works — CSR

Client-Side Rendering — the server sends a bare shell, and React builds the whole UI in the browser.

01

Request

The browser asks the server for the page.

02

Empty HTML

The server responds with a bare shell.

03

JS Download

The browser fetches the React bundle.

04

Render

React builds the UI on the client.

Pros

Rich, dynamic interactivity once the app has loaded.

Cons

Slow first load · weak SEO · JavaScript required.

Rendering — 02

What is SSR?

Server-Side Rendering — HTML is generated on the server, per request. The browser receives fully populated HTML, immediately.

01

Request

The browser asks the server for the page.

02

Server Renders

HTML is generated on the server, per request.

03

Immediate Paint

Content is visible right away — no blank screen.

04

Hydration

React attaches interactivity to the HTML.

Pros

Fast first paint · better SEO · accessible content.

Cons

More server load · interactions wait for hydration.

Net result: better SEO and initial-load performance.

Deep Dive — 01

The App Router

Replaces the old /pages directory with a powerful, nested structure — everything lives in app.

file treeapp/
app/
├── page.tsx            # /
└── dashboard/
    └── page.tsx        # /dashboard

Routes = Folders

Every folder under app maps to a URL segment — no manual route configuration.

Nested Layouts

Layouts persist across their children — no remounting between pages.

Special Files

page · layout · loading · error. A folder only becomes a public route once it holds a page.

Deep Dive — 02

Server Components —
the new default.

Every component in the App Router is a Server Component — unless you explicitly say otherwise.

Zero Client Bundle

Server Components never ship to the browser — no impact on your JavaScript bundle size.

Direct Backend Access

Query databases and read secrets safely, right inside the component.

Opt-in Interactivity

Add the "use client" directive only where you need state and events.

Server — the default
page.tsx layout.tsx fetch data db access secrets
Client — the island
"use client" state events browser APIs

Deep Dive — 03

Data fetching — before & after.

The Old WayReact · Client
useEffect(() => {
  fetch('/api/data')
    .then(res => res.json())
    .then(setData)
}, [])

Requires state, effects — and every fetch happens on the client.

The New WayNext.js · RSC
export default async function Page() {
  const res = await fetch('https://api.xyz/data')
  const data = await res.json()

  return <h1>{data.name}</h1>
}

Async components — fetching directly on the server.

Shared UI for a segment and its children — persistent headers and footers that never remount.

page.tsx

The unique UI of a route segment — its presence is what makes a route public.
